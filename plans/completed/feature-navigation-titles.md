# Фича: заголовок из `###`-комментария в навигации (`Ctrl+G`)

## Цель

Сейчас в попапе `Ctrl+G` запрос без `@name` показывается как `METHOD URL`
(`navigation.go:57`), а осмысленный заголовок `### Создать запись` перед ним парсер
выбрасывает (`parser.go:56-58`). Нужно: если у запроса нет `@name`, использовать текст
после `###` как название и показывать его в списке — как название запроса — как в
JetBrains/VS Code REST Client (заголовок блока `###` = имя запроса).

## Предпосылки

- `buildNavEntries` (`navigation.go:47`) строит label из `r.Name` либо `METHOD URL`.
- `ParseFile` (`httpfile/parser.go:14`) сбрасывает `Request` в `flush()` и не хранит
  текст `###`-сепаратора.
- Токен `TokSeparator` с полем `Value = line` (`lexer.go:61-64`) уже содержит весь
  текст `### …`, но `ParseFile` парсит заново, не через `Lex`.
- Тест `parser_test.go:5` (`TestParseSimple`) использует `### Get todos` / `### Create`.

## Дизайн

1. В `httpfile/model.go` добавить в `Request` поле `Title string` — текст после `###`
   у сепаратора, который открывает блок запроса (пусто, если сепаратора нет).
2. В `parser.go` перед `flush()` в ветке `###` сохранять `cur.Title = trimPrefix(line)`
   (текст после лидирующих `#`, `TrimSpace`). Так заголовок привязывается к следующему
   запросу, а для запроса без сепаратора остаётся пустым.
3. В `navigation.go` (`buildNavEntries`) приоритет имени: `r.Name` → иначе `r.Title`
   → иначе `METHOD URL`. `search` строится из выбранного label.
4. i18n: новых ключей не требуется (заголовок — это контент файла, а не UI-строка;
   status-строки `nav.jumped` уже параметризованы). Повысить приоритет: `@name`
   остаётся главным именем, `###`-заголовок — фолбэком.
