# Фича: смена окружения / профили переменных

## Цель

Несколько именованных наборов переменных (dev / prod / qa) с hotkey-переключением —
типичный сценарий .http-клиента (аналог Environments в Postman, Request Environments
в JetBrains).

## Предпосылки

- База переменных и подстановка — см. plans/feature-variables.md (это раздел 3 того
  плана; выполнять после feature-variables).
- Персист-настройки: `internal/settings` + `appsettings.yml`.

## Дизайн

- Профили хранить в `appsettings.yml` (поле `profiles: map[string]map[string]string`)
  или в отдельном файле окружений.
- Активный профиль показывать в шапке/статус-баре.
- Приоритет значений: активный профиль > локальная секция `@var` в файле > дефолт.

## Чек-лист

- [ ] Поле `Profiles map[string]map[string]string` + `ActiveProfile string` в
      `internal/settings/settings.go`.
- [ ] UI: хоткей и команда в action menu для выбора профиля (попап как
      `actionmenu.go`).
- [ ] Отображение активного профиля в шапке/статус-баре.
- [ ] При запуске подставляются переменные активного профиля (см. feature-variables).
- [ ] Переключение профиля перерисовывает предпросмотр/подсветку переменных.
- [ ] Тесты: выбор профиля, приоритет профиль > дефолт, фолбэк на дефолт.
- [ ] README.
- [ ] Новые UI-строки выносить ключами в i18n (см. plans/i18n.md).

## Terms of Done

- [ ] Смена профиля меняет фактические значения, подставляемые в `{{var}}`.
- [ ] Без настроенных профилей поведение не меняется (существующие тесты зелёные).
- [ ] `go test ./...` и `go build -o bin/curlyk.exe ./cmd/curlyk` проходят.
