# Добавление фичи в проект curlyk

Server — проектирование фичи до написания кода. Результат — plan-документ
`plans/feature-<slug>.md`, который потом реализуется скиллом
`curlyk-feature-implement`.

## Где живут планы

- Открытые (ещё не реализованные) фичи: `plans/feature-<slug>.md`.
- Реализованные: перемещаются в `plans/completed/` (см. коммит `f4b9480`).

Существующие открытые планы: batch-run, collapse-blocks, import-openapi-postman,
profiles, response-history, response-search, save-response. Перед добавлением
проверь, нет ли уже похожего плана.

## Формат плана (строго придерживайся)

Заголовок `# Фича: <краткое имя>`, затем секции:

- **## Цель** — что делает фича и зачем, 1–2 строки, с аналогом в других
  инструментах, если уместно (Postman Environments, JetBrains и т.п.).
- **## Предпосылки** — на что опирается фича: конкретные поля/функции/файлы
  (`app.go:46`, `keys.go`, `internal/settings/…`), зависимые планы
  (`plans/feature-variables.md`). Укажи, какую фичу надо сделать первой, если
  есть зависимость.
- **## Дизайн** — архитектурное решение: где хранить данные, какой хоткей,
  какой механизм переиспользуется (saveAs, actionmenu, i18n).
- **## Чек-лист** — маркированный список `- [ ] …` задач реализации с
  указанием реальных файлов/функций. Сюда же: тесты, README, i18n.
- **## Terms of Done** — маркированный `- [ ] …` список приёмки: что должно
  работать, и всегда финальная строка `go test ./...` +
  `go build -o bin/curlyk.exe ./cmd/curlyk`.

## Правила наполнения

1. Перед написанием прочитай релевантный код: `internal/tui/keys.go` (занятость
   хоткеев), `internal/tui/app.go`, `internal/settings/settings.go`,
   `internal/i18n/`. Указывай реальные имена файлов/полей в чек-листе.
2. Все новые UI-строки выносить ключами в i18n — добавь пункт со ссылкой на
   `plans/i18n.md`.
3. Тесты обязательны — добавь пункт в чек-лист.
4. README — если фича пользовательски заметна, добавь пункт.
5. Slug в имени файла — kebab-case по смыслу фичи, например `feature-save-response.md`.

## Готово

Файл создан в `plans/feature-<slug>.md`. Не коммить без просьбы. Скажи, что
план готов и что реализация — через скилл `curlyk-feature-implement`.
