# Design

## Context

Мотивация — в `proposal.md`. Требования — в `specs/desktop-gui/spec.md`.

Текущее состояние, важное для подхода:

- `internal/gui` уже содержит самодостаточный виджет `Editor` (буфер `doc`,
  подсветка `highlighter`, отрисовка только видимых строк, выделение, клипборд,
  undo/redo, поиск `findState` на общем `internal/search`).
- Окно (`app.go`) — три панели в `HSplit`, строка статуса, верхняя строка
  (заголовок или поиск), оверлеи автодополнения и меню запроса рисуются
  рендерером редактора.
- Панель ответа — тот же `Editor` в режиме `SetReadOnly(true)`, текст кладётся
  готовой строкой из `formatResponse`; подсветки и поиска там нет, фокус панели
  не отслеживается.
- Общие пакеты уже вынесены: `internal/httpfile` (парсинг и `FormatJSONBody`),
  `internal/jsonlex` (лексер JSON), `internal/search` (поиск подстрок),
  `internal/completion`, `internal/profiles`, `internal/curl` (импорт/экспорт
  curl). В TUI остались локальные `isCurlCommand`, данные справки и попап
  навигации.
- `go test ./...` зелёный при `CGO_ENABLED=1`; TUI собирается без cgo. Работа
  GUI ещё не закоммичена.

## Goals / Non-Goals

**Goals:**

- Довести поведение окна до паритета с TUI по возможностям, перечисленным в
  спеке, не дублируя логику парсинга, поиска и подсветки.
- Переиспользовать существующий `Editor` для панели ответа и справки, чтобы
  выделение, копирование и прокрутка работали одинаково во всех панелях.
- Вынести оставшиеся общие куски (распознавание curl, модель справки) в
  пакеты без UI, чтобы TUI и GUI не расходились.

**Non-Goals:**

- Релизная упаковка GUI, иконка и Windows-ресурсы `cmd/curlyk-gui`.
- Встроенный в окно файловый менеджер, вкладки, сплиттеры с сохранением
  пропорций, темы Fyne (палитра берётся из `internal/theme`).
- Повторение TUI-хоткеев там, где они конфликтуют с платформенными привычками:
  в GUI `Ctrl+Y` остаётся «повторить», `Ctrl+Shift+Z` добавляется как алиас;
  «удалить строку» из TUI в GUI не переносится.
- Отладочный дамп `Ctrl+D`, выход по `Esc Esc`/`F10` — окно закрывается
  штатными средствами ОС.

## Decisions

### 1. Панель ответа — тот же `Editor` с режимом подсветки, а не отдельный виджет

`Editor` получает режим `highlightResponse` и номер строки-разделителя
(последняя строка блока «дамп запроса + статус + время + заголовки ответа»).
Строки до разделителя рисуются нейтральным цветом, строки после — сегментами
`jsonlex`, уже используемого для тел запросов.

Почему: выделение, клипборд, прокрутка, поиск и виртуализация уже реализованы в
`Editor`; отдельный просмотрщик пришлось бы учить всем этим вещам заново.
Альтернатива — `widget.RichText` для ответа — отвергнута: нет построчной
виртуализации, другое поведение выделения и поиска.

`formatResponse` возвращает текст и число строк заголовочной части; `setResponse`
вызывает `resp.SetResponseText(text, headerRows)` и сбрасывает прокрутку.

### 2. Поиск по ответу — существующий `findState` + верхняя строка поиска

Поиск остаётся в `Editor` (общий `internal/search`). Верхняя строка поиска
(`u.searching`) получает цель `searchTarget` (редактор или ответ). Пока активна
панель ответа, печатный символ открывает строку поиска, `Ctrl+F` делает то же;
`Enter`/`↓` и `Shift+Tab`/`↑` вызывают `resp.FindNext/FindPrev`, счётчик берётся
из `resp.FindCurrent/FindMatches`. `Esc` закрывает поиск и вызывает
`resp.ClearFind`.

Почему: одинаковые совпадения в TUI и GUI, никакого второго алгоритма.
Альтернатива — `widget.Entry` поверх ответа — не даёт подсветки всех совпадений.

Замечание: `revealMatch` двигает каретку; для read-only панели это безопасно,
редактирование блокируется в `TypedRune`/`TypedKey`.

### 3. Активность панелей и `Tab`

`resp.SetOnFocus` (новый хук) вызывает `setActive(paneResp)`, клик по панели
файлов уже вызывает `setActive(paneFiles)`. `Tab`/`Shift+Tab` обрабатываются в
`windowKey` редактора: при фокусе в редакторе — переход на ответ и обратно, при
фокусе в ответе — обратно в редактор; в боковой панели `Tab` передаётся списку.
Когда открыта строка поиска, `Tab` не перехватывается — иначе нельзя выйти из
поля ввода.

Почему: Fyne доставляет `Tab` сфокусированному виджету, а не окну; централизация
в key hook даёт предсказуемый порядок и не ломает навигацию внутри списков.

### 4. Справка: общая модель в `internal/help`, рендер — у каждого интерфейса

Из TUI выносится список записей «клавиша + ключ i18n» и секция переменных в
`internal/help` (структуры, без lipgloss). TUI продолжает рисовать их своими
стилями; GUI строит из той же модели `widget.List`/`VBox` в правой панели.

Почему: сейчас список хоткеев в TUI — единственный источник правды; дублирование
в GUI неизбежно разъедется при следующем хоткее. Альтернатива — оставить список
только в TUI и вручную повторять в GUI — отвергнута.

Состояние: `u.helpVisible`, автоматически `true`, пока `u.lastBody` пуст и
ответа ещё не было; `F1` инвертирует; `setResponse` сбрасывает в `false`.

### 5. Навигация `Ctrl+G` — `widget.PopUp` с полем фильтра и списком

Новый `internal/gui/nav.go`: при открытии парсит буфер (`httpfile.ParseFile`),
строит записи `@name → ### title → METHOD URL`, показывает `widget.Entry`
(фильтр) и `widget.List`. `Up`/`Down`/`Enter`/`Esc` перехватываются кастомным
`TypedKey` у поля фильтра, чтобы каретка не уезжала; `Enter` закрывает попап,
ставит каретку на строку запроса и обновляет статус.

Почему: нативный попап Fyne сам держит фокус и закрывается по клику вне; ручной
оверлей в рендерере (как в TUI) потребовал бы своей геометрии и обработки мыши.
Альтернатива — модальное окно `dialog` — тяжелее и блокирует окно.

### 6. Конвертация cURL: общий предикат в `internal/curl`

`isCurlCommand` из `internal/tui/clipboard.go` переезжает в `internal/curl` как
`IsCurlCommand`. TUI вызывает общий вариант. GUI: `Editor` получает хук
`SetPasteHandler(func(text string) (string, bool, error))`; окно подставляет
`curl.ImportLine`, вставляет результат одним шагом undo и сообщает статус, а при
ошибке разбора показывает `err.convertCurl` и не меняет буфер.

Почему: предикат — часть контракта импорта curl, а не TUI. Хук нужен потому, что
`Paste` живёт в виджете, а строка статуса — в окне.

### 7. Профили: клик открывает и активирует профиль

Боковая панель получает строки профилей, открывающие файл в редакторе (как TUI:
`openProfile` одновременно делает профиль активным). Сохранение идёт общим
`saveFile`; после записи `profiles.Load` при следующем запуске читает новый файл.

Почему: поведение TUI уже описано и привычно; отдельная «только активация»
развилка создала бы третье поведение. Риск случайной правки снимается тем, что
файл открывается явным кликом по строке профиля.

### 8. Иконка `▶` в гуттере — отрисовка + hit-test, без отдельных виджетов

При изменении текста редактор кэширует множество строк, начинающих запросы
(`httpfile.ParseFile`). Рендерер рисует `▶` в гуттере для этих строк, `Tapped`
сначала проверяет попадание в область иконки и вызывает `onRunIcon(row)`; окно
открывает существующее меню запроса. Иначе клик обрабатывается как позиция
каретки.

Почему: отдельный кликабельный объект на строку свёл бы на нет виртуализацию.
Альтернатива — рисовать иконку только для видимой строки каретки — хуже
обнаруживается.

### 9. Дамп запроса в ответе

`formatResponse` добавляет после `METHOD URL` заголовки отправленного запроса из
`res.Request.Header` (с нормализацией `\r\n`), затем статус, время, заголовки
ответа, тело. Порядок и разделители фиксируются, чтобы `headerRows` для
подсветки считался детерминированно.

### 10. Чистка i18n

Ключи `gui.open/save/saveAs/new/themeButton/lineNumbers/showResponse/run/
langButton/status/untitled`, на которые ссылается только тест переводов,
удаляются; недостающие для новых элементов (`gui.help*`, `gui.nav*`,
`gui.editProfile`, `gui.pasteConverted`) добавляются в оба языка. Тест
`TestGUIStringsAreTranslated` переводится на реально используемые ключи.

## Risks / Trade-offs

- **Попап навигации перехватывает `Tab`/стрелки** → кастомный `TypedKey` у поля
  фильтра; тест на перемещение выбора стрелками и `Enter`.
- **Подсветка ответа зависит от корректного `headerRows`** → разделитель
  вычисляется в `formatResponse`, а не эвристикой по пустой строке; тест на
  ответ с пустыми строками в теле.
- **Поиск в read-only панели двигает каретку и сбрасывает выделение** → это
  допустимо (поиск — навигация); тест подтверждает, что текст ответа не
  меняется.
- **`Tab`-переключение конфликтует с полями ввода** → перехват только в
  редакторе/ответе, не в строке поиска и не в фильтре попапа.
- **Вынос справки и `IsCurlCommand` затрагивает TUI** → рефакторинг без смены
  поведения; существующие тесты `internal/tui` остаются зелёными.
- **Иконка в гуттере усложняет hit-test** → тест на клик по иконке и на клик
  рядом с ней (каретка, а не меню).

## Migration Plan

Миграции данных нет: формат `appsettings.yml`, профилей и `.http` не меняется.
Порядок выкладки — обычный коммит в основную ветку после зелёных
`go test ./...`; откат — revert коммита, TUI от выноса общих пакетов не зависит
функционально.
